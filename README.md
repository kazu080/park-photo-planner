# Park Photo Planner

パークで「どこに立つか・光がどう当たるか・何mmで撮るか」を一緒に考える、非公式の撮影支援Webアプリです。

## Macで起動する

1. このフォルダを好きな場所に置きます。
2. `start.command` をダブルクリックすると、ブラウザで開きます。
3. 停止は起動したターミナルで **Control + C**。

Python 3 が必要です。このMacでは動作確認済み。Node.js・npm・APIキー・ビルド作業は不要です。Pythonが見つからない場合は起動時に案内を表示します。

コマンドから起動する場合：

```sh
cd "/アプリを置いた場所/park-photo-planner"
python3 server.py
```

標準URLは `http://localhost:8765`。使用中なら次の空いているポートを自動で選び、画面にURLを表示します。HTMLファイルを直接開かず、上記の方法で起動してください。

## スマホで使う

Macとスマホを同じWi-Fiに接続し、`start-mobile.command` をダブルクリック。ターミナルに表示されたスマホ用URLをSafari／Chromeで開きます。Macは起動したままにしてください。ファイアウォールの設定によって接続できない場合があります。

Macの同じWi-Fi接続がない現地では、このローカル起動だけでスマホから接続できません。**現地で独立して使うには、このフォルダの静的ファイルをHTTPS対応ホスティングへ配置する必要があります。** データベース・サーバー側計算は不要です。公開は本納品では行っていません。

現在地とオフライン用の画面保存は、ブラウザの安全な接続（HTTPSまたはlocalhost）が必要です。LAN経由のHTTPでは地図をタップして位置を指定してください。HTTPSで一度開けばアプリ画面をキャッシュできますが、地図タイルはオフライン保存しません。オフラインでは、既存設定と座標入力による計算が利用できます。

## 使い方

- ① 被写体、② 撮影位置を選んで地図をタップ。ピンはドラッグでも移動できます。
- ランドは城と花火、シーは帆船とハーバーを描いた夜のテーマで表示。背景の装飾はアプリ内のオリジナルイラストです。
- ランド／シーの初期表示を切り替えられます。シー選択時はメディテレーニアンハーバー中央（通常地図の「ビリーヴ！」アイコンの位置、約35.6261912 / 139.8863250）に被写体ピンと地図中心を設定します。初期ピンは仮位置で、推奨観覧位置ではありません。
- 地図右上の「通常地図／航空写真」で切り替え。表示の選択も自動保存します。航空写真は国土地理院の全国最新写真（シームレス）を使用し、撮影時点の景観を表示します。航空写真表示中は表示可能な縮尺までの縮小に制限します。
- 撮影日と日本時間を指定。スライダーは00:00〜23:59を1分単位で動かせます。
- フルサイズ／APS-C 1.6×、縦／横位置、構図、被写体サイズを設定。
- 「どこから撮ればいい？」では、テレ端の実焦点距離を1つ入力。被写体を中心に、その焦点距離で選んだ構図を撮れる距離の円を表示します。円周がテレ端の目安、内側はズームを引いて撮れる範囲です。ワイド端は入力・判定しません。
- センサー・構図・焦点距離は地図の上で変更でき、円の大きさも更新。地図タップや①のドラッグで円の中心を移動します。このモードには撮影位置ピンや撮影位置の結果カードは表示しません。
- 円周の色で全方向の光を表示し、希望する光の方向は円の内側で強調します。時間スライダーは円の距離を保ったまま光の向きを更新します。
- 設定はブラウザ内に自動保存。設定JSONの書き出し／読み込みでMacからスマホへ移せます。

## 計算の基準

距離は緯度・経度から球面距離で求めます。高低差は含みません。

**必要実焦点距離(mm) ≈ 距離(m) × センサー寸法(mm) × 画面占有率 ÷ 被写体サイズ(m) × 実用補正**

- 初期占有率：80%。10〜100%で変更可能。
- 補正：0.50〜1.50倍。小さくすると余白が増えます。
- センサー：フルサイズ36×24mm、APS-Cは各寸法を1.6で割ります。
- 顔／バスト／上半身／全身は高さ基準。フロート全体は幅基準。
- 仮のサイズ：顔0.30m、バスト0.65m、上半身0.95m、全身1.75m、フロート幅8m。キャラクターやフロートの実寸ではありません。
- フロート選択時は横位置に切替。必要なら縦位置に変更できます。
- **実焦点距離**を表示。APS-C時は35mm判換算値も補助表示します。
- 例：10m先、高さ1.75m、フルサイズ縦位置、占有率80%、補正1.00 → 約165mm。APS-C 1.6×なら約103mm（換算約165mm）。
- 円の半径(m) = テレ端(mm) × 被写体サイズ(m) ÷ センサー寸法(mm) ÷ 画面占有率 ÷ 実用補正。例：200mm・全身1.75m・縦位置・80%・補正1.00なら、フルサイズで約12.2m、APS-Cで約19.4m。
- 円の内側は、必要焦点距離がテレ端以下となる範囲です。近距離で実際のワイド端や最短撮影距離の制限がある場合は、現地で調整してください。大きな円が航空写真の縮尺に収まらない場合は通常地図を使用してください。

太陽は [NOAA General Solar Position Calculations](https://gml.noaa.gov/grad/solcalc/solareqns.PDF) の近似式で計算します。日本時間（UTC+9）固定、方位は北0°・東90°、高度は幾何学的高度で大気差を含みません。撮影計画用の概算です。

被写体から見た「撮影位置の方位」と「太陽方位」の差で分類：

| 方向差 | 表示 |
|---|---|
| 0〜30° | 順光 |
| 30°超〜75°未満 | 斜光 |
| 75〜105° | サイド光 |
| 105°超〜180° | 逆光（斜め後ろの光も含む） |

太陽高度0°以下では昼の光判定を停止。光の選択に関係なく、夜間も焦点距離の円は表示します。太陽高度60°超では頭上の光の案内を表示します。

## 実用上の限界

- 建物・樹木の影、雲、地形の遮蔽、被写体の顔の向きは考慮しません。
- おすすめ範囲は道路・水面・建物の内部も含みます。立入／観覧可能かは現地の案内に従ってください。
- 焦点距離は遠距離の画角の近似。最短撮影距離、フォーカスブリージング、レンズ歪みは反映しません。
- 現在地のGPS誤差は撮影距離に対して大きくなることがあります。近距離では地図や数値入力で補正してください。
- スマホとMac、異なるブラウザでは自動保存は共有されません。
- 地図表示にはネット接続が必要です。外部への通信はOpenStreetMap／国土地理院の地図タイル取得のみ。設定はアプリ側サーバーに送信しません（地図事業者には表示範囲のタイル要求が送られます）。

## 構成・検証

依存ライブラリLeaflet 1.9.4を同梱。その他の計算・UIは標準JavaScript、ローカル起動はPython標準ライブラリです。通常地図は [OpenStreetMap](https://www.openstreetmap.org/copyright)、航空写真は [国土地理院の地理院タイル（全国最新写真）](https://maps.gsi.go.jp/development/ichiran.html#seamlessphoto)。Leafletのライセンスは `vendor/LEAFLET-LICENSE.txt`。

`node test.mjs` で97件の計算チェックを実行できます。太陽の参照例、夜間、光の分類、球面距離／方位、センサー寸法、焦点距離と逆算、焦点距離範囲の端点、テレ端の円と内側の判定、補正を確認します。
